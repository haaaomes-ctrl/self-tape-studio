## Summary

`knowledge/60-finance/` is the corpus area for TapeCoach's **finance reasoning** — dated,
read-only finance snapshots and the why behind money decisions. It is the home of the
`cfo` advisory role's output. The finance **data** lives in the owned Supabase (DS-04,
DS-06, DS-13, DS-16, DS-17); this area holds the **read** of it and the reasoning on top,
never the system of record.

Snapshots are generated by the `tc-finance-snapshot` skill as
`60-finance/<YYYY-MM-DD>-cfo-finance-snapshot.md`. The `cfo` agent reads the finance views
read-only, cites every figure, surfaces the downside, and never estimates ungrounded.

## Context / why

Finance is the one axis the corpus previously had no home for: the data slices (DS-04
credit ledger, DS-06 partner pools, DS-13 consumer revenue, DS-16 AI-cost baseline, DS-17
CFO dashboards) and the in-app `cfo-dashboard.server.ts` exist in code, but there was no
advisory role to read them, no place to record the finance picture over time, and no
contract keeping that read honest and structurally read-only. The `cfo` role +
`tc-finance-snapshot` skill + this area fill that gap. The CFO is **advisory and
read-only**: recommendations go to the SRO and become BA items built by the engineer pair
via PR — the CFO never mutates money, pricing or config. See
`00-meta/AGENT-ECOSYSTEM.md` §CFO for the full contract.

## Detail

**Folder number.** `60-finance` is the next free top-level number: the documented vault
scheme is `10-research` / `20-decisions-context` / `30-conversations` / `40-product-ideas`
/ `50-marketing`, with `90-archive` last; `50` is taken (marketing), so finance takes
`60`, slotting before the archive.

**Grounding corrections (verified against the live schema, 2026-06-08).** Recorded so the
queries don't drift:

- The DS-17 CFO dashboard views (`cfo_monthly_burn_dashboard`,
  `cfo_revenue_milestone_dashboard`, `cfo_report_cost_by_report_dashboard`,
  `cfo_report_funding_dashboard`, `cfo_free_report_subsidy_dashboard`,
  `cfo_paid_credit_liability_summary`, `cfo_partner_margin_dashboard`,
  `cfo_revenue_ledger_dashboard`, `cfo_partner_revenue_source_dashboard`) live in the
  **`public`** schema — **not** a separate "private" schema as the DS-17 migration comment
  reads. They are "private" by **grant**: SELECT is granted to `postgres`/`service_role`
  only, not to `anon`/`authenticated`.
- p50/p95 cost-per-report and cost-by-partner/source/duration already exist as **columns**
  (`ai_usage_cost_dashboard.{p50,p95}_report_cost_usd`,
  `ai_usage_cost_grouping_summary`) — the snapshot reads them, it does not recompute
  percentiles.
- Revenue milestones in the live view are exactly £100 / £300 / £1,000 / £2,500
  (`cfo_revenue_milestone_dashboard.milestone_gbp`), matching
  `CFO_REVENUE_MILESTONES_GBP` in `src/server/cfo-dashboard.server.ts`.
- Planning constants (ChatGPT/Codex £200, Lovable £22, fixed burn £275, USD→GBP 0.8,
  margin guardrail 0.70) are surfaced **in the burn view** and mirrored in
  `cfo-dashboard.server.ts`; they are planning assumptions, not measured spend.
- Synthetic/canary runs are flagged in the data (`synthetic_usage`,
  `commercial_metrics_excluded`); commercial figures must respect them.

The full verified view/column list lives in the `tc-finance-snapshot` skill — that skill
is the single grounding anchor for finance queries.

## Open questions

- **Structural read-only Supabase path (interim today).** The CFO's read-only guarantee is
  currently enforced by (a) the `cfo` agent's tool grant omitting every mutation tool and
  (b) the `tc-finance-snapshot` SELECT-only rule — a **contract**, not yet **structural**:
  the MCP `execute_sql` path can technically run DML. The structural fix is a dedicated
  read-only Postgres role (`USAGE` + `SELECT` on the finance views only, no write grants
  anywhere) that the finance read path connects through, or running the Supabase MCP in
  `--read-only` mode. That needs a DB migration via the operator's merge protocol (or an
  MCP reconfiguration), so it is a **BA item for the engineer pair**, not something the
  advisory CFO can or should do itself. Until then, treat finance read-only as interim.
