# Regenerate the delta + drift register

One comparison engine, two directions. It surfaces gaps and drift for the operator; it never decides. The SRO health-check.

## Write-boundary (strict)

Writes **exactly one file**: `knowledge/00-meta/DELTA-REGISTER.md`. Reads code/tests **read-only**; never edits code, the spine, or `docs/**`. Conflict resolution defers to the spine (README wins).

## The two questions

1. **Forward delta (gap):** where does current reality fall short of target? **Target = the atomised README requirements appendix** (each requirement has an id and a priority — the BA agent's output), plus roadmap slices and ADR invariants. Current = the code and `current`-status notes.
2. **Drift:** do two controlling sources contradict each other now (spine-vs-spine), or does the code contradict the spine (spine-vs-code)?

## Judging current state

Judge primarily from **tests and types** (compact, intent-encoding, trustworthy). Where uncertainty remains, **read the implementation or relevant PRs** to confirm. **Never assert what you cannot verify** — mark it `unverified`. An `unverified` row is better than a wrong "implemented"; we take on no debt.

## Prioritisation

Sort gaps by the **requirement's priority** (set during atomisation), then bump **drift above not-yet-built gaps** of equal priority (an existing contradiction is more urgent than an unbuilt feature), and weight the **active roadmap section first**.

## Output format

```markdown

## Forward gaps (target not yet met) — by priority

| Requirement (id) | Priority | Source | Current state | Verdict | Notes |
| ---------------- | -------- | ------ | ------------- | ------- | ----- |

## Drift — spine vs spine

| Source A | Source B | Conflict | Controlling (README wins) |

## Drift — spine vs code

| Spine fact | Code location | Divergence | Severity |

## Unverified (could not confirm)

- <item> — <why>

## Summary

- Gaps: G (high-priority: h) | Spine-vs-spine: X | Spine-vs-code: Y | Unverified: U
```

## Report

Lead with the highest-priority gaps and any drift — operator decisions. Suggest which gaps could become roadmap slices; state which source is controlling for drift, but do not edit the spine or code — propose changes via PR. If a gap exists because reasoning was never captured, suggest `tc-conversation-ingestion`. If the requirements appendix does not exist yet, say so — the register is only as good as that checklist.
