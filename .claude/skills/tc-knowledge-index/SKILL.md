# Regenerate the corpus index

`INDEX.md` keeps the spine lean by holding all spine→evidence linking _outside_ the spine, as a derived artifact.

## Write-boundary

This skill writes **exactly one file**: `knowledge/00-meta/INDEX.md`. It reads the spine and corpus but never modifies the spine, `docs/**`, or code.

## Inputs

1. **Spine headings** — scan and collect headings (and ADR ids) from `README.md`, `AGENTS.md`, `CLAUDE.md`, `tapecoach-v3-roadmap.md`, files under `docs/architecture/adr/`, and `docs/tapecoach/s10-*`. Keep the heading text as written (e.g. `## Core doctrine`, `### 1.6 Calibration doctrine`, `### Track H — Audition take lifecycle and admin reports`).
2. **Corpus notes** — scan every `knowledge/**/*.md` with corpus front-matter. Read `id`, `status`, `spine_anchor`, `tags`, `decided_ref`.

## Anchor resolution

Each note's `spine_anchor` is a tolerant label like `"README §1.6 Calibration doctrine"` or `"ADR-0003"`. Resolve it by **case-insensitive substring match** of the label's section text against the scanned headings (and ADR ids). A label that resolves to no heading goes in the **Unresolved anchors** section — never alter the spine to make it match.

## What to build

Group by resolved spine heading. Under each, list supporting notes, but only `current` and `decided` notes count as **live** support. List `exploratory` notes under "in-progress" and `superseded` ones under "history", so the index never implies a fossil is current.

Then compute three signal sections:

- **Documentation gaps** — spine headings with zero `current`/`decided` support. Controlling facts whose reasoning is undocumented.
- **Orphan notes** — notes with empty `spine_anchor`. Flag them, but pure research/history may legitimately stand alone (judge by `tags`); do not force a link.
- **Unresolved anchors** — `spine_anchor` labels matching no heading. These are note-side typos or stale labels to fix.

## Output format

Write `knowledge/00-meta/INDEX.md` exactly in this shape:

```markdown
# Corpus Index (generated)

> Generated by tc-knowledge-index on <YYYY-MM-DD>. Do not hand-edit.

## Spine anchor → evidence

### AGENTS §Core doctrine

- **decided** — [[ai-is-report-brain-rationale]] (high)

### README §1.6 Calibration doctrine

- **decided** — [[score-calibration-professional-rationale]] (high)
- _exploratory_ — [[partial-brief-threshold-idea]]

### ADR-0003

- **decided** — [[analysis-runtime-cloudflare-rationale]] (high)

## Documentation gaps (controlling facts with no live evidence)

- AGENTS §Simplest mental model (step 6, operator loop) — no current/decided note
- roadmap §Track H Audition take lifecycle — undocumented

## Orphan notes (no spine anchor)

- [[discipline-rubric-musical-theatre]] — research; stands alone (ok)
- [[idea-batch-comparison-ui]] — proposal; consider linking to roadmap §Track G

## Unresolved anchors (label matches no heading — fix the note)

- [[some-note]] → "README §Professional scoring" (no such heading; nearest: "1.6 Calibration doctrine")

## Counts

- Headings scanned: N | Notes (current/decided/exploratory/superseded): a/b/c/d
- Gaps: G | Orphans: O | Unresolved: U
```

## How to run it

Prefer a deterministic scan over reading every file by eye — a short script that parses YAML front-matter and spine headings is more reliable and repeatable. If you write one, keep it in `.claude/skills/tc-knowledge-index/` so it is reusable. The script must only write `knowledge/00-meta/INDEX.md`.

## Report

Give the user the counts and, most usefully, the top documentation gaps and any unresolved anchors. If gaps relate to live behaviour, suggest `tc-conversation-ingestion` on the relevant threads or drafting the missing spine documentation as a PR proposal (which the operator applies — this skill never edits the spine).
